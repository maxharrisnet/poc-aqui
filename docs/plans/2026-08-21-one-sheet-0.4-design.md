# One sheet (v0.4): design

**Goal:** Fold the watchlist into the inventory. One Google Sheet, one row per
title, whether the shop owns copies of it or only wants one. One tab in the
interface. The watchlist sheet, module, endpoint and tab go away.

**Decisions taken (Max, 2026-08-21):**

| | Decision |
|---|---|
| Tab name | Inventory |
| Watchlist tab | Removed, not kept as a saved view |
| Check listings now | Prices every watched pressing, same as a sweep |
| Storage | Append columns to the existing inventory sheet. Nothing migrated; the watchlist sheet is simply no longer read |

## Why

Spec v0.2 §3 kept two sheets because of grain: watchlist one row per album
wanted, inventory one row per physical copy. What got built is one row per
title with a `qty` column, which is the watchlist's grain. The inventory row
already carries `watching`, `max_landed_mxn` and `alert_sms`: it is a watchlist
row with stock columns on it, and the watchlist sheet is the subset of titles
with no stock and no shelf price. Per-copy truth belongs to the retail core and
the intake step, both still marked "not built" on the Technical page.

## Data model

`src/inventory.ts` owns the schema. Column order is the sheet contract: the
seventeen existing columns stay exactly where they are, nine are appended, and
the range becomes `A:Z`.

| # | Column | Type | Blank reads as | Notes |
|---|---|---|---|---|
| 1–17 | existing `id` … `last_purchased_at` | | unchanged | |
| 18 | `master_id` | number | null | Discogs master; blank where a release has none |
| 19 | `watched_release_ids` | csv of numbers | `[]` | What a sweep prices. Empty means "just `release_id`" |
| 20 | `pressing_scope` | `all` \| `selected` | `all` | From the adaptive pressing rule |
| 21 | `pressing_count` | number | 0 | Vinyl versions known at add time |
| 22 | `last_checked_at` | ISO date | null | |
| 23 | `best_landed_mxn` | number | null | Cheapest landed cost in the last check |
| 24 | `best_release_id` | number | null | Which pressing was cheapest |
| 25 | `status` | `watching` \| `alerted` | `watching` | `alerted` means the last check crossed the limit. Alerts fire on the crossing only |
| 26 | `active` | boolean | **true** | Soft delete. Blank is true so every existing row survives the change |

Dropped from the watchlist and not carried over: `priority` and
`min_condition` (no interface ever set them; `min_condition` cannot be enforced,
spec v0.2 §5.2), and the `acquired` and `paused` statuses (derivable now).

**Derived, never stored:**

- On the shelf: `qty > 0`
- Out of stock: `qty === 0` and the title has been bought before (`landed_cost_mxn` set or `last_purchased_at` set)
- Wanted: `qty === 0` and never bought
- Needs restocking: out of stock or at/under `min_qty`. A wanted title never needs restocking
- `sweepReleaseIds(item)`: `watched_release_ids` if non-empty, else `[release_id]`, else `[]`

`ensureHeaders` already extends a short header row. `patchInventoryItem` also
extends it from the grid it has just read, so the first write after deploy
labels the new columns without an extra API call. Reads never depend on the
header.

## API

`/api/inventory`

- `GET`: unchanged shape `{ items, sheetUrl }`. Returns every row; the page hides `active === false`.
- `POST { releaseId } | { query }`: what `/api/watchlist` POST did, landing on the inventory.
  - Resolve the release (a `query` goes through `searchRelease`, as a desk search does).
  - Look for an existing row, active or not, whose `release_id` equals it or whose `watched_release_ids` contains it.
  - Found: patch `watching: true, active: true` if either is off. Respond `{ item, existed: true, wasWatching }`. Nothing is duplicated.
  - Not found: `getRelease`, `getMasterVersions`, `planPressings` exactly as before. New row: `qty 0`, no prices, `watching true`, `alertSms false`, `thumbUrl` and `year` from the release, `status watching`, `active true`. Respond `{ item, plan }`.
- `PATCH`: existing fields, plus `active` (boolean). Turning `watching` off resets `status` to `watching`, so a record watched again later alerts on its next crossing.

`/api/sourcing?id=<inventory id>`

- Replaces `?releaseId=&q=`. Loads the row, runs the shared per-record sweep over `sweepReleaseIds`, writes `last_checked_at`, `best_*` and `status` back, and responds with
  `{ checkedAt, fxDate, checked, under, discogs: { …cheapest pressing }, item, links }`.
  `checked` is the number of pressings priced; `item` is the row as written, so the page repaints from it.

`/api/stream?mode=watchlist`: unchanged contract. Sweeps rows where `active && watching`.

`/api/watchlist`: deleted. `WATCHLIST_SHEET_ID` is no longer read anywhere.

## Sweep

`src/run.ts` gains `sweepRecord(item, fx)`: prices each of `sweepReleaseIds`,
keeps the cheapest, decides `belowThreshold`, composes the SMS on a crossing
(`alertSms && status !== "alerted"`), patches the row, returns the
`CheckResult`. Errors and "nothing listed" are handled as today. `runWatched`
(was `runWatchlist`) loops it over active watched rows, least recently checked
first, capped at `MAX_SWEEP_ITEMS`. `/api/sourcing` calls the same function, so
the button and the sweep cannot disagree.

## Interface

**Tabs:** Buying desk · Inventory · How it works · Technical. The Watchlist tab,
panel, CSS and JS are removed.

**Inventory tab, top to bottom:**

1. Hero. Bullets gain "Add records by name" and lose nothing else; the sheet bullet says stock and watches live in one sheet.
2. Summary strip: titles · copies · capital · retail · need restocking · **watched**. "Titles" counts rows that are or have been on the shelf; wanted rows show up under "watched".
3. **Add records**: the repeater from the old tab, one empty row to start, placeholder "Artist and title", button "Add to inventory". Adds run one at a time (Discogs rate limit). Row status: Added · Now watching · On the shelf, now watching · Already watching · No match · Failed.
4. Filters, as views: **All · On the shelf · Wanted · Needs restocking · Watched**, plus the text filter. The Watched view is the old watchlist.
5. List. Folded rows add one line under the price: `best $X · checked 3m ago`, or `not priced yet`, for watched rows; marked when the best price is under the limit. Wanted rows read "Wanted" where out-of-stock rows read "Out of stock".
6. Detail panel additions: the Watch & alerts status line shows "Under your alert price" when `status === 'alerted'`, and the best seen line; the Discogs section says how many pressings are watched ("6 pressings watched", "1 of 143 known"); Sourcing's status reads "Pricing N pressings…" while a check runs; a **Remove from the inventory** link appears on rows with `qty === 0` and patches `active: false`.
7. Actions row: **Check my watchlist** (runs `mode=watchlist`, results on the desk, reloads the inventory when done) and Refresh from the sheet.

**Buying desk:** unchanged in layout. Watch / Watching posts to `/api/inventory`
and un-watching patches `watching: false` (never `active`). The per-release
maps the desk paints from (`watched`, `thresholds`, `alerts`) are built in
`loadInventory` from active watched rows over `sweepReleaseIds`. Threshold and
SMS controls on a result row patch the inventory row. The hero bullet says
Watch adds the record to the inventory as wanted.

**Technical page:** text only, geometry untouched.

- "Two kinds of storage" bullet → one table in a sheet for now; what a database adds later.
- Stack chips: Google Sheets (the inventory: stock, watches, limits, one row per title); Inventory database (where these rows go once the till feeds them, one row per copy).
- Flowchart nodes: Watchlist · Google Sheets becomes the watched rows of the inventory; Inventory · database tooltip says one row per title today.

**README:** the Watchlist section becomes "Inventory and watchlist (v0.4)": one
sheet, `INVENTORY_SHEET_ID` only, what Watch and Add do, the pressing rule and
the Sheets pitfalls carried over. Interface section lists four tabs. Files list
drops `watchlist.ts`.

**questions-for-ian.md #4:** one line on what the tool does today (per-title
floor and a watch switch on the same row).

## Scripts

- `check-sheets`: one target, app range `A:Z`.
- `seed-inventory`: seeds the nine new fields with their defaults.
- `enrich-inventory`: also resolves the master and pressing plan for rows whose `watched_release_ids` is empty and `release_id` is set, so seeded rows sweep every pressing once enriched. Until then they sweep their own pressing, which is correct and free.

## Tests

`src/inventory.test.ts` (new; there was none): header count equals row width;
round trip; a seventeen-column legacy row reads `active true`, `status
watching`, `watchedReleaseIds []`; short rows; `resolveRowNumber`;
`sweepReleaseIds` fallback. `watchlist.test.ts` is deleted. `pressings.ts`
imports `PressingScope` from `inventory.ts`.

## Errors

Unchanged policy: config guidance passes through, Sheets failures are
translated by `publicSheetsError`, everything else is logged and replaced.
`WATCHLIST_SHEET_ID` leaves the allowlists. A failed sheet write during a sweep
still never discards results already paid for.

## Out of scope

Pressing picker for masters above the limit. Per-copy rows. The scheduled
sweep itself. Renaming env vars, routes or modules.

## Rollout

1. Merge to `main`, deploy. The first write extends the header row to `Z`.
2. `WATCHLIST_SHEET_ID` can be deleted from Vercel and `.env.local` at leisure; nothing reads it.
3. Optional: `npm run enrich-inventory` fills masters for the seeded rows.
4. Prod runs entirely on `INVENTORY_SHEET_ID`: the inventory sheet must be shared with the service account before this ships.
